# 代码审查规则

按风险从高到低检查：

1. 远程页面是否获得 Node、文件、Shell、任意 IPC 或越权导航能力。
2. 配置损坏、只读、升级和跨平台路径场景是否可能造成数据丢失或静默失败。
3. 单实例、延迟启动、托盘隐藏、窗口销毁和 timer 清理是否存在状态竞争。
4. Windows、macOS、Linux X11/Wayland 的能力差异是否被正确检测、降级并记录。
5. 错误处理是否可能留下白屏、重复窗口、永久重试或不可退出的 Kiosk 状态。
6. 测试是否验证用户可见行为，而非只验证 mock 被调用。
7. 日志和提交内容是否包含 Token、Cookie、代理凭据、用户数据或本机路径等敏感值。

审查结论先列出明确问题，附文件和行号；没有发现问题时说明覆盖范围及未完成的验证，不用格式性建议掩盖风险。
