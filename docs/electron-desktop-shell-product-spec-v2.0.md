# Electron 通用桌面客户端产品规格说明书

> **已废弃：** 本 v2.0.0 文档为 Windows 单平台基线，已被 `electron-desktop-shell-product-spec-v2.1-cross-platform.md` 替代。

**文档版本：** v2.0.0  
**编制日期：** 2026-10-28  
**产品形态：** Windows Electron 桌面客户端  
**交付形态：** 标准安装版 + 绿色免安装 ZIP 版

## 1. 产品目标

封装一个高可靠、易部署、可现场配置的通用 Electron 桌面外壳，用于承载指定的 HTTP/HTTPS Web 业务系统。

客户端应支持：

- 交付前直接预置 `config.json`，客户开箱即用；
- 配置文件损坏、缺失或网址无效时进入本地配置界面；
- 适配普通办公 PC、展厅大屏、触控一体机和无人值守场景；
- 支持网络代理、断网重试、托盘驻留、全屏、置顶、开机自启和延迟唤醒；
- 支持单实例运行和现场运维入口；
- 安装版不强制写入受保护的系统目录；
- 绿色版解压后即可运行，不依赖安装程序。

## 2. 范围与非目标

### 2.1 本期范围

- Windows 桌面客户端主程序；
- 本地配置文件和可视化配置界面；
- Web 页面加载、离线重试和窗口管理；
- 系统托盘、单实例、开机自启和延迟展示；
- 安装版、绿色 ZIP 版及配置文件交付；
- 本地日志和基础故障诊断。

### 2.2 本期不包含

- 独立的 API 反向代理服务器；
- 业务系统本身的登录、权限和数据逻辑；
- Windows Shell 替换、组策略锁定或真正的操作系统级数字标牌模式；
- 自动更新服务，除非另行增加更新服务器、签名和回滚方案。

## 3. 运行环境与交付约束

- 首期支持 Windows 10/11 64 位；如需 ARM64，必须单独构建和验收。
- Electron 版本在实施时锁定为当前稳定版本，并写入构建清单，不允许每次打包自动漂移。
- 安装包、主程序和绿色版程序均应进行代码签名。
- 安装版默认使用当前用户安装模式，默认路径为用户可写目录；允许用户选择其他目录。
- 禁止把标准安装版默认安装到 `C:\Program Files` 等系统保护目录。
- 绿色版交付为 ZIP 目录包，解压后目录结构完整；除非专门验证 Portable 单文件路径逻辑，不交付单文件自解压版。

## 4. 总体运行流程

客户端启动后按以下状态机运行：

```text
启动
  -> 获取单实例锁
  -> 解析配置路径
  -> 读取并校验 config.json
      -> 失败：打开配置界面
      -> 成功：进入启动策略
  -> 初始驻留状态（托盘/最小化）
  -> 等待延迟时间
  -> 创建或显示主窗口
  -> 加载目标网址
      -> 成功：正常运行
      -> 失败：显示离线页并按间隔重试
```

第二次启动时不得创建新窗口，应向已有实例发送唤醒请求。已有实例在托盘中时，应显示并聚焦主窗口；已有实例正在倒计时时，应取消倒计时并立即显示。

## 5. 配置文件管理

### 5.1 配置文件位置

配置文件名称固定为 `config.json`。

主路径：

- 标准安装版：主程序 `.exe` 同级目录；
- 绿色 ZIP 版：ZIP 解压根目录，和主程序 `.exe` 同级。

如果主路径因权限或文件系统策略不可写，程序不得静默失败，应显示明确错误。产品可配置启用备用路径 `%LOCALAPPDATA%\\Vendor\\App\\config.json`，并在配置界面显示当前实际使用路径。

### 5.2 读取与校验规则

- 文件不存在、JSON 语法错误、字段类型错误或目标网址无效时，打开配置界面；
- 无效文件不得直接覆盖，先保存为 `config.json.invalid.<时间戳>`；
- 对未知字段保持兼容，不因多余字段导致启动失败；
- 使用 `schemaVersion` 管理配置迁移；
- 配置保存必须采用临时文件写入后原子替换，并保留最近一次有效配置备份；
- 配置界面未保存时关闭，不应修改原配置。

### 5.3 配置界面

配置界面必须为本地页面，不依赖目标业务网址。

界面至少包含：

- 目标网址；
- 窗口模式、全屏、置顶和置顶层级；
- 代理模式、代理地址和绕过规则；
- 开机自启、初始驻留状态和延迟秒数；
- 配置快捷键开关和快捷键组合；
- 保存、取消、恢复默认值和测试连接。

保存前必须执行完整校验。保存成功后默认执行一次受控重启，使所有窗口策略一致生效；写入失败时不得重启。

## 6. 推荐配置结构

```json
{
  "schemaVersion": 1,
  "targetUrl": "https://example.com",
  "window": {
    "mode": "fullscreen",
    "alwaysOnTop": false,
    "alwaysOnTopLevel": "normal",
    "display": "primary",
    "closeAction": "hide"
  },
  "network": {
    "proxyMode": "direct",
    "proxyServer": "",
    "proxyBypass": "",
    "retryIntervalSec": 3,
    "requestTimeoutSec": 20,
    "offlinePageEnabled": true
  },
  "startup": {
    "openAtLogin": false,
    "initialState": "tray",
    "delaySec": 0,
    "delayOnlyOnLogin": false,
    "showAfterDelay": true
  },
  "maintenance": {
    "hotkeyEnabled": true,
    "hotkey": "Ctrl+Alt+Shift+F12",
    "trayConfigEnabled": true
  },
  "security": {
    "allowedOrigins": [],
    "allowExternalLinks": false,
    "allowPopups": false,
    "allowDownloads": false
  },
  "logging": {
    "level": "info",
    "retentionDays": 14
  }
}
```

### 6.1 字段规则

- `targetUrl`：必填，仅允许 `http://` 或 `https://`，必须能被标准 URL 解析器解析并包含主机名。
- `window.mode`：`window`、`fullscreen`、`kiosk`。
- `alwaysOnTopLevel`：`normal`、`floating`、`pop-up-menu`、`screen-saver`。
- `window.display`：`primary` 或具体显示器 ID。
- `network.proxyMode`：`direct`、`system`、`fixed`、`pac`。
- `startup.initialState`：`tray` 或 `minimized`。
- `startup.delaySec`：整数，范围 0～3600。
- `maintenance.hotkey`：仅作为当前客户端窗口获得焦点时的快捷键，不得注册为系统全局快捷键。
- 代理账号密码不得明文存储在 `config.json`；如业务必须使用认证代理，使用系统凭据存储或首次运行时输入。

## 7. 目标网址与网络行为

### 7.1 页面加载

- 初始网址只允许 `http://` 或 `https://`；
- 默认禁止任意新窗口和弹窗；
- 外部链接默认禁止，允许时使用系统默认浏览器打开；
- 默认禁止下载、通知、摄像头、麦克风、USB 等权限；
- 页面导航和重定向默认限制在 `allowedOrigins` 内；为空时默认允许目标网址的源。

### 7.2 断网重试

- 页面加载失败时不得停留在 Chromium 默认错误页；
- 显示本地离线提示页，并展示最近一次错误类型和重试状态；
- 默认每 3 秒重试一次，可在配置中调整；
- 仅对主框架加载失败进行重试；
- 页面成功加载后立即取消重试定时器；
- HTTP 404/500、TLS 证书错误和接口请求失败需要区分记录；
- 网络恢复且目标服务正常时，应在 3～10 秒内恢复页面；
- 窗口关闭、退出程序或切换配置后必须清理重试定时器。

## 8. 代理能力

### 8.1 客户端代理

- `direct`：不使用代理；
- `system`：跟随 Windows 系统代理；
- `fixed`：使用代理服务器地址；
- `pac`：使用 PAC 地址或规则。

代理切换必须对后续页面请求生效，并关闭或刷新旧连接，避免旧连接继续使用旧代理。

### 8.2 反向代理边界

“API 前缀反向代理”和“自动补 CORS 响应头”不属于本客户端基础代理能力。若业务确实需要，应作为独立本地代理模块或服务另行设计、开发和安全评审。

## 9. 窗口、全屏和置顶

- `window`：普通窗口，可调整大小；
- `fullscreen`：隐藏边框和菜单，进入系统全屏；
- `kiosk`：适用于展厅和无人值守场景，禁止普通用户退出或打开新窗口。

置顶层级必须按 Windows 10/11、单显示器和多显示器分别验收。`screen-saver` 级别只表示最高置顶策略，不承诺覆盖 UAC 安全桌面、锁屏界面或企业安全软件窗口。

必须提供维护退出路径：配置快捷键、托盘菜单或启动参数至少保留一种可用方式。

## 10. 开机自启与延迟展示

- `openAtLogin=true` 时注册当前用户的 Windows 登录启动项；
- `delayOnlyOnLogin=true` 时，延迟只对开机启动生效，手动启动立即执行；
- 延迟期间保持 `tray` 或 `minimized` 状态；
- 延迟结束后才加载目标网址并应用全屏、Kiosk 和置顶状态；
- 托盘菜单“立即显示窗口”应取消倒计时并立即展示；
- `delaySec=0` 表示不等待，立即执行显示逻辑；
- 开机自启被系统策略、任务管理器或安全软件禁用时，应记录日志但不反复弹窗。

## 11. 托盘与运维入口

托盘右键菜单固定包含：

- 打开配置界面；
- 重新加载网页；
- 立即显示窗口；
- 退出程序。

窗口关闭按钮默认执行 `hide`，不退出进程；退出必须通过托盘“退出”或配置界面明确操作完成。

快捷键默认值为 `Ctrl + Alt + Shift + F12`。快捷键关闭后不得再监听该组合键，但托盘配置入口默认仍可用，除非 `trayConfigEnabled=false`。

## 12. 安全要求

- 远程网页不得启用 Node.js 集成；
- 开启上下文隔离和沙箱；
- preload 只暴露最小化、白名单 IPC；
- 限制页面导航和新窗口创建；
- 默认拒绝权限请求；
- 不允许远程页面直接访问本地文件、执行命令或读取任意本地路径；
- 日志不得记录代理密码、Cookie、Token 或业务敏感数据；
- `http://` 仅作为兼容选项，生产环境优先使用 HTTPS。

## 13. 单实例行为

- 客户端必须启用单实例锁；
- 第二次启动不能创建第二个主窗口；
- 第二次启动应向已有实例发送唤醒请求；
- 已在托盘时显示并聚焦；
- 已在延迟倒计时中时取消倒计时并立即显示；
- 配置窗口已存在时，聚焦配置窗口而不是重复创建。

## 14. 日志与诊断

日志目录建议为 `%LOCALAPPDATA%\\Vendor\\App\\logs`，默认保留 14 天。

至少记录：

- 客户端版本和 Electron 版本；
- 配置文件实际路径；
- 启动来源（手动/开机自启/第二次启动）；
- 代理模式；
- 页面加载成功、失败和重试信息；
- 全屏、置顶、托盘和配置保存结果；
- 配置解析错误和权限错误。

## 15. 安装与升级

### 15.1 标准安装版

- NSIS 安装包；
- 当前用户安装为默认；
- 支持自定义安装目录；
- 安装目录中保留 `config.json`；
- 升级不得覆盖用户配置；
- 卸载时询问是否保留配置和日志。

### 15.2 绿色版

建议目录结构：

```text
Client/
  Client.exe
  config.json
  resources/
  locales/
  logs/
```

解压后直接运行，不写入注册表以外的强制安装目录；如启用开机自启，允许用户明确确认。

## 16. 验收标准

### 16.1 配置

- 同级目录存在有效 `config.json` 时，不弹配置窗口；
- 配置缺失、损坏或网址无效时，自动打开本地配置界面；
- 保存后文件内容与界面一致，重启后配置仍有效；
- 文件只读或目录无权限时，显示明确错误路径，不得假装保存成功。

### 16.2 窗口

- 可验证普通窗口、全屏和 Kiosk 三种模式；
- 置顶级别在 Windows 10/11 上按配置生效；
- 多显示器模式下窗口出现在指定显示器；
- 不将“覆盖 UAC/锁屏/安全桌面”作为通过条件。

### 16.3 网络

- 断网启动时显示自定义离线页；
- 恢复网络且目标服务正常后 3～10 秒内自动恢复；
- 代理模式切换后新请求使用新代理；
- HTTP 错误、DNS 错误和 TLS 错误均可在日志中区分。

### 16.4 启动与托盘

- 开机自启配置可在 Windows 设置或任务管理器中看到；
- 延迟误差不超过 ±1 秒；
- 托盘、最小化、立即显示和退出操作符合定义；
- 第二次启动只唤醒已有实例。

### 16.5 运维安全

- 快捷键只在客户端窗口获得焦点时生效；
- 关闭快捷键后，快捷键不再打开配置界面；
- 托盘配置入口按 `trayConfigEnabled` 正确控制；
- 远程页面不能访问 Node、本地文件或任意系统命令。

### 16.6 测试矩阵

至少覆盖：

- Windows 10/11；
- 标准用户和管理员用户；
- 安装目录包含空格、中文和非系统盘；
- 单显示器和双显示器；
- 任务栏正常显示和自动隐藏；
- 网线断开、Wi-Fi 断开、恢复网络；
- 有代理、无代理、代理切换；
- 配置文件缺失、损坏、只读、被占用；
- 睡眠唤醒和重复启动；
- 配置快捷键开启和关闭。

## 17. 发布前必须冻结的决策

以下内容在开发前必须由产品方确认：

1. 绿色版采用 ZIP 目录版，还是必须支持单文件 Portable；
2. 配置主路径不可写时是否允许自动切换到用户目录；
3. Kiosk 模式下的最终维护退出方式；
4. 是否允许外部链接、下载和弹窗；
5. 业务是否确实需要 API 反向代理；
6. 是否需要多显示器指定屏幕；
7. 是否需要自动更新及更新回滚机制；
8. 支持的 Windows 最低版本和 CPU 架构。

---

**版本结论：** 本 v2.0 规格已将原方案中的配置、代理、全屏置顶、延迟启动、快捷键、断网恢复、安装权限、安全边界和验收条件具体化，可作为开发排期、测试用例和客户交付清单的基线。
